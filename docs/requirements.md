# 需求與驗收

## 公共需求來源與邊界

- 內政部[國土空間資訊數位基礎建設及加值應用計畫（114–118 年，即 2025–2029 年）](https://www.moi.gov.tw/News_Content.aspx?n=13876&s=315991)提供空間資訊整合與加值的政策背景；[臺中市政府地理資訊網](https://giscloud01.taichung.gov.tw/GISMap/about.aspx)是公開運作的圖資查詢、統計、開放下載及介接案例。
- [臺北市公園基本資料](https://data.taipei/dataset/detail?id=ea732fb5-4bec-4be7-93f2-8ab91e74a6c6)公開行政區、座標、設施及開放時間；[臺北市體育局運動場地位置表](https://data.taipei/dataset/detail?id=d540c002-9946-498b-bc88-1040db9e344f)公開行政區、類別和經緯度。它們只做公開欄位及需求參考，沒有抓取、分發或宣稱完整覆蓋。全國場館名冊未使用。
- 下表列出本系統的可重現驗收門檻。合成分區雖採 WGS84，形狀、名稱、人口與點位均不代表實際街廓或設施。

## 使用流程與範圍

盤點人員先以來源欄位確認資料，依類別及範圍篩選，檢查供給與加權近接缺口，與一個基準分區比較，最後匯出可追溯的分析結果。利害關係人可共同檢視權重假設，據此安排現勘；不是依分數自動核定預算或施工。

納入：本地 GeoJSON 匯入／拒絕回報、來源和授權顯示、三類設施、地圖鍵盤操作、範圍切換、排序公式、基準差、雙種匯出、手機。
不納入：即時資料源、地圖瓦片、網路服務區、無障礙路線、設施容量或開放時段、帳權／多使用者、地址定位、認證或生產 SLA。

## 可重現驗收口徑

| ID | 本示範驗收方法 | 通過條件 | 證據 |
|---|---|---|---|
| D-01 | 開啟範例 | 6 區、22 設施、18 需求點；分析不依賴外網 | 模型測試 1、瀏覽器 Overview |
| D-02 | 以鍵盤選地圖；公共運動篩選；切換分區與基準 | 支援 Enter／空白鍵；顯示 6 個運動點；基準差更新；分區僅顯示其圖層 | 瀏覽器 filter、baseline、mobile |
| D-03 | 700 m 固定合成測試，構造近／遠各 3 點 | 已知近／遠判定 6/6，未近接比例 0.5，公式結果一致 | 模型測試 3；另測跨區及半徑單調性 |
| D-04 | 資料缺失與異常 | 無需求點不排名；座標錯、重複 ID、未定義區域拒絕；失敗不覆寫 | 模型測試 6、7；瀏覽器 import |
| D-05 | 匯出原始資料及分析 | 保留來源／授權；分析帶入設定和幾何；只輸出目前範圍；多餘欄位不帶出 | 模型測試 8；瀏覽器 export |
| D-06 | 390 px 瀏覽器執行與截圖 | 頁面無橫向溢位；只有寬表局部可捲動 | 瀏覽器 mobile |
| D-07 | 導覽及文字 | 有可見焦點、地圖選取不只靠顏色、表格提供同一結果 | 互動測試；未進行完整 WCAG 稽核 |

測試標籤只對已建構的合成資料有效，**6/6 不是現實可達性準確率**。上線前須取得正式資料來源、建立版本治理、驗證行政區拓樸與路網、確認合法使用、資安稽核及使用者測試。
